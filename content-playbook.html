How everything nests together

Before touching content, get the structure straight — every downstream step (the checklist, the tracker sheet, the node mapping) assumes this hierarchy.

↳ Hover a number on the diagram for more detail.

1
Learning Path
The overall program. Contains multiple Courses. Example: "AI Fundamentals Learning Path."
↓ contains
2
Course (= Master Playground)
One subject end-to-end. Has its own description, access type, and — at this level only — one Intro video and one Outro video.
↓ contains
3
Module (= Individual Playground)
One topic within the course. Has its own title, learning objectives, and a sequence of nodes.
Video Reading / Markdown Question repeats per video in the module
Note on Intro / Outro / End node: Intro and Outro videos live at the course level only — one Intro before Module 1, one Outro after the last module. There is no separate "end node" screen per module; a module simply ends on its last node and moves into the next module.
SME / Trainer
The person who researches, decides structure, writes content, and builds the course. In this team, SME and Trainer are the same person.
Ops POC
Receives the draft structure and checklist, helps configure the Playground platform, and joins the final review.
Node
A single step inside a module — a video, a reading/markdown block, or a question.
Course Flow
The pattern a module follows: Video + Question, Video + Markdown, Question only, etc. Decided per module.

B. Per-module structure

Repeat this group for every module in the course.
Playground / module title
e.g. "Fine-Tuning Strategies."
Learning objectives
What learners should be able to do after this module. Use action words: identify, explain, create, analyze.
Node structure
The sequence of content inside the module. e.g. "Video 1 → Reading → Question → Video 2 → Question."
Node titles
The title shown for each section/activity. e.g. "Watch: What is AI?", "Knowledge Check."
Course flow
How content is fed for this module.

C. Content assets

Per video / per module, as applicable.
Video content
The script, talking points, or explanation the video should cover.
Reference content
Supporting material learners can check after each video — articles, PDFs, guides, links.
Question content
Every quiz question, its answer choices, the correct answer, the message shown on a correct answer, and the pop-up shown on a wrong answer.
Branching / remediation logic
Plain-language instructions on what happens after wrong answers — e.g. "3 wrong attempts → send the learner back to the previous video" or "→ move on to the next video regardless." This is fully custom per course; write it out clearly for Ops.

D. Course-level intro & outro

Filled once per course — these bookend the entire course, not each module.
Intro content
The opening video script: welcomes learners, explains what each module covers, gives general instructions.
Outro content
The closing video script: congratulates the learner and lays out next steps.
01
// Phase 1

Plan

Turn a course idea into a documented structure before any deck or video work starts.

Think of it asThe blueprint stage
Lives underRequirement checklist — Groups A & B
Built fromResearch draft, content-type decisions, branching rules
Wraps up withA documented draft, shared with Ops
1.1

Initial research

Structure your research top-down: Course Name → Module Titles → Video Titles within each module. This is a draft — it doesn't need to be final.

Share this draft, together with the requirement checklist, with your Ops POC. This gives them an early look at the whole shape of the course while you keep refining content.

1.2

Choose the content type per module

Decide whether each module needs questions after it, just readable content, a downloadable file, or some combination. This decision is the Course Flow field in the checklist, and it's made per module:

  • Video/Slide + Question
  • Video/Slide + Markdown + Question
  • Video/Slide Only
  • Video/Slide + Markdown
  • Question + Markdown
  • Question Only
1.3

Define branching logic & draft questions

If a module uses questions, write out — in plain instructions for Ops — what happens after a wrong answer. For example: "If a user gets 3 questions wrong, send them back to the previous main video" vs. "…let them move on to the next video regardless." There's no fixed platform rule here; every course can define this differently, so be explicit.

Alongside the branching rule, provide for every question:

  • The question text and all answer choices
  • The correct answer
  • The message shown when the correct answer is selected
  • The pop-up message shown when a wrong answer is selected

// Phase 2

Draft & document

Turn the plan into real content, and get it all reviewed before a single slide is designed.

Think of it asTurning the blueprint into real words
Lives underThe tracker sheet — new course tab
Built fromDeck content, voiceover scripts, Claude-assisted drafts
Wraps up withSign-off, before production starts
2.1

Draft deck content & voiceover scripts

For every video, produce two things: the content that goes on the deck (on-slide text) and the voiceover script that will be recorded over it. You can draft this solo, brief someone else with a doc, or use an AI model — after the first pass of research, we typically bring in Claude to help shape this content.

// Sample Claude prompt — starting point for this step. Swap in your own version if your team prefers different phrasing. 
You're helping build a training module for an internal AI learning Playground.
I'll give you the module topic, learning objectives, and research notes.

For every slide/video section, produce two things:
1. Deck content — short on-slide text: a headline plus 2-4 supporting bullets
   or a single clear visual concept. Not full narration, just what appears
   ON the slide.
2. Voiceover script — the full narration for that slide, written to be read
   aloud naturally (conversational, contractions are fine, no unexplained
   jargon).

House style to follow:
- Explain the "why" before the "how."
- Use one concrete example per concept — a side-by-side comparison, a real
  scenario, or a worked example instead of an abstract analogy.
- Don't use meta-phrases like "in this section we will discuss" — teach the
  concept directly.
- Keep each slide to one idea.

Module: [module title]
Learning objectives: [paste objectives]
Research notes / outline: [paste your research]

Output as a numbered list of slides, each with a "Deck:" line and a
"Script:" line.
2.2

Log everything in the tracker sheet

Add a new tab named after your course in the shared tracker sheet, and record all four things from Phase 1–2 there: structure, content-type decisions, branching + question content, and deck content + scripts. Use the standardized column template so every course tab looks the same.

2.3

Get sign-off

Get the documented tab reviewed before moving into deck production. Catching structure or content issues here is far cheaper than catching them after the deck and video are built.

// Phase 3

Produce

Build the actual assets: deck, video, and the course's intro/outro bookends.

Think of it asWhere the course becomes watchable
Lives underCanva + Google Vids
Built fromThe approved script and deck content from Phase 2
Wraps up withA finished deck, video, and course intro/outro
3.1

Build the deck in Canva

Use Canva, and follow the house style exactly — see the full Canva Style Guide for every spec (fonts, sizes, colors, animation, spacing) and the sample decks to start from instead of a blank canvas.

3.2

Create the videos

  1. Add transitions to the finished Canva deck.
  2. Generate the voiceover using Google Voice or ElevenLabs — the voice must sound natural, not robotic. There's no fixed voice or preset; it's your call per course, as long as it reads naturally.
  3. Download each slide, or a group of slides, timed to match the voiceover — as an MP4 (to keep Canva's own animation) or a PNG (static), depending on what that section needs.
  4. Assemble the clips and voiceover in Google Vids.
3.3

Create the course intro & outro

Build these in Google Vids using an avatar presenter — persona is your choice per course. Both sit at the course level, not per module:

  • Intro — plays before Module 1. Explains what each module in the course covers and gives general instructions.
  • Outro — plays after the final module. Congratulates the learner and lays out next steps.
04
// Phase 4

Launch

Bring everything into the platform, get eyes on it one last time, and ship.

Think of it asWhere it becomes real for learners
Lives underThe Playground platform
Built fromEvery asset, mapped to its node
Wraps up withA joint review and a live course
4.1

Map content into the Playground

Upload and map the intro video, every module's videos/decks, markdown/reference content, and questions (with their branching logic) into the Playground platform, following the node structure documented in the tracker sheet.

4.2

Final review

Review the live Playground end-to-end — markdown, content, videos, question flow, branching — together with the Ops POC, the SME, and any other reviewers on the team. See Roles & Responsibilities.

4.3

Go live

Once sign-off is complete, release the course. Update its status in the tracker sheet.

When something looks broken

Common symptoms, and what actually causes them.

!
Learners get stuck repeating a question endlesslyThe branching/remediation logic wasn't written clearly, or wasn't handed to Ops at all — see Phase 1.3.
!
A module's deck feels inconsistent with the rest of the courseThe Canva style guide wasn't followed exactly — check font, sizes, and animation against the style guide.
!
The voiceover sounds like it's reading slide bullets out loudDeck content and voiceover script were drafted as one thing instead of two — see Phase 2.1.
!
A course's tracker tab looks different from every other courseIt wasn't built on the standardized column template.
!
Intro or outro video is missing, duplicated, or shows up per moduleRemember: Intro/Outro live at the course level only, never per module.
!
Reviewers keep sending a course back after production has already startedSign-off (Phase 2.3) was skipped or rushed before moving into deck/video production.
